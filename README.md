# cc-retain-lab

CC_Codex 二期（26.11）**数据工程**产品线：**留存裁撤台**（FastAPI + 原生 JS SPA + SQLite）。

## 一句话骨架（自有，非外仓抄题）

**分区留存策略版本 → 到期扫描裁决 → 归档或销毁执行 → 策略与实物分区对账**

与现有六线正交（不是采集目录、ETL 管道、同步源、解析入库、编排流、种子摄取）。  
也不碰外仓常见指纹（Feed 归并 / 作业编排 / CDC 游标 / 质检签发 / 贴源-明细-汇总）。

## 领域

- **所属领域**：数据工程  
- **子方向**：数仓与数据湖（分区留存 / 裁撤闭环）

## 技术栈

| 层 | 选型 |
|----|------|
| 后端 | Python 3.12、FastAPI、Uvicorn、SQLite |
| 前端 | 原生 JS 单页（全中文），青灰底 + 铜强调，顶栏导航（非绿侧栏克隆） |

## 基线已通主链

1. 现行留存策略（主题域 / 保留天 / 到期动作）  
2. 实物分区列表（在线 / 归档 / 销毁）  
3. 按基准日到期扫描 → 生成待执行裁决  
4. 单条裁决执行（归档写地址 / 销毁清零）  
5. 策略与实物对账报告

## 基准日冻结与并发回灌（retain-bug-14 修复）

- **单一判定依据**：到期扫描以调用方传入的 `as_of_date` 为冻结基准日，`scan_jobs.as_of_date`（开单快照）与每条裁决的裁决年龄同源计算，墙钟（`date.today()`）不得顶替，未到期分区不再误入列表。
- **三页同基准**：
  - 扫描队列：`基准日（冻结快照）` 与 `提交墙钟`（`created_at`）分列，互不顶替；
  - 裁决卡片：展示 `开单基准日` 与按其同源计算的 `裁决年龄`；
  - 实物分区：可选基准日，按基准日核算 `裁决年龄 / 保留天 / 基准日到期`。
- **并发回灌防护（缺一不可）**：进程级 `threading.Lock` 串行化开单 + 连接 `BEGIN IMMEDIATE` 立即取写锁 + `judgments` 唯一部分索引（同一分区至多一张 `待执行/执行中` 裁决）。缺锁时并发补跑会让同一分区双成功推两次，三层防护后仅一张生效。
- **执行占用**：裁决执行改为条件 `UPDATE ... WHERE status IN ('待执行','已失败')`，并发双击仅一条 200、其余 409。
- **基准日校验**：非法日期在扫描 / 对账 / 分区接口统一返回 400。
- 本机库重算：不同基准日重扫得到不同到期集合，页面展示全部绑定基准日，可核验。
